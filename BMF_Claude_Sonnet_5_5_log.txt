## 2. Required architecture

Implement modular components for:

- **Patent input representation:** patent title, abstract, VLM-generated figure descriptions, patent identifier, owner/company metadata, and optional source-span references.
- **Semantic evidence extraction:** structured concepts, relations, semantic roles, evidence spans, source modality, and extraction confidence. Use a consistent schema for training and inference.
- **M/P/R/I classification:** four category scores, predicted class, and supporting semantic evidence.
- **Concept Lattice:** construct the formal context from training patents and extracted concepts; implement formal concept analysis using clearly defined object-attribute incidence relations. Preserve concepts shared across categories.
- **Category relevance:** implement the mathematical scoring functions in the specification, including the definition and normalization of concept-to-patent matching weights.
- **Evidence provenance:** preserve links from every extracted concept and relation to the patent and source passage or figure description.
- **Technical capability graph:** aggregate patent-level concepts and relations into a company-level graph without treating company identity as a shortcut for the M/P/R/I classifier.
- **Organizational inference:** represent candidate organizational structures and estimate their plausibility from the technical capability graph and any available independent organizational evidence.

## 3. Mathematical fidelity

## 4. Organizational inference constraints

Patent evidence reveals technical capabilities; it does not directly reveal a company's actual departments or reporting hierarchy.

- Distinguish observed technical capabilities from inferred organizational hypotheses.
- Do not claim that organizational probabilities are calibrated unless validated against suitable ground-truth data.

- In that situation, implement a clearly labeled baseline or candidate-generation interface, document its assumptions, and identify the data required for a trainable probabilistic model.
- Preserve uncertainty, alternative candidate structures, and evidence provenance.
- Allow abstention when the available evidence cannot distinguish between competing organizational hypotheses.

Task complete 
The audit corrections are in and all 50 tests pass (31 earlier tests, updated where behaviour changed, plus 19 new regression tests in tests/test_audit.py). Everything still runs only on synthetic data, so there is no accuracy, calibration or trained teacher–student result to report.

Classification

 - Empty-intent concept: it matched every patent and injected the training label frequencies as if they were evidence. It is now excluded from the scores, contributions and denominator by default. include_empty_intent=True restores the literal sum over all concepts, and a test shows the artifact.
 - Priors: they are stored separately as class_priors and never enter the evidence scores.
 - No evidence: the raw scores are all 0, the softmax is None and the prediction abstains. A softmax of zeros would have faked a uniform distribution. The same applies when every matched concept has zero relevance.
 - Naming: raw_scores, softmax_scores (not calibrated) and calibrated_probabilities (raises until the temperature is fitted on held-out data) are now distinct in the API and docs.
 - Equations checked:
  - Concept-to-category relevance matches an independent evaluation of the spec formula.
  - Binary patent-to-concept matching equals lattice extent membership for every training patent and concept.
  - Hand-computed tests show scores moving correctly when evidence is added or removed.
 - Bug caught on the way: reordering Prediction's fields briefly put the prediction and supporting evidence in the wrong fields. A provenance test caught it and I fixed it.

Organizational inference

 - Edge weights: co-occurrence and direct relation counts are stored separately, and the weight is a_cooc·cooc + a_rel·rel. The two coefficients default to 1 each, which is unvalidated, and cooc_weight=0 uses relations only.
 - Modularity: it now validates that the partition is disjoint and covers exactly the graph's nodes. Isolated nodes are handled and tested.
 - M/P/R/I grouping: it is opt-in, because nothing in the spec says organizational units mirror the four categories.
 - Patent-only abstention: abstention is the default when no independent organizational evidence applies, since patents alone cannot tell technical clusters from organizational units. The result lists the missing evidence, and allow_patent_only=True returns technical-cluster candidates only.
 - External constraints: I added an external_constrained candidate built from the independent same-unit assertions.
 - Adversarial tests: two tests pass. Two technical clusters with a same-unit assertion resolve to a single unit. Two always co-occurring capabilities with a different-unit assertion resolve to separate units.
 - Scores: they are named compatibility_score and are not probabilities.

Behaviour changes you will see

 - Example output: in the synthetic example, AcmeCo now abstains (only one candidate structure remains). Patent-only runs need allow_patent_only=True.
 - Renamed fields: the old scores and probabilities names are gone from ConceptScorer and Prediction.
